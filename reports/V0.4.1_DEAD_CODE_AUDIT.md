- **Note:** The test's own comment says "7 bytes: [rda]OK5D" which is itself incorrect (it's 9 bytes), but the assertion `response_len == "9"` is correct.

### 5.1 Must-Include Components

1. **SMC3 Protocol Module** (`smc3_protocol.py`):
   - `smc3_frame(motor, position)` — Position command encoding
   - `READ_COMMANDS` — Uppercase readback commands

   - Timeout handling with configurable `--read-timeout`

3. **Sweep Generation** (`sweep.py`):

   - `positions_for(motor, offset)` — Multi-motor position calculation

   - Consolidated `FakeSerial` with full `serial.Serial` interface
   - `create_response_sequence()` helper
   - Error injection support

5. **Analysis Pipeline** (`analysis/analyze_h3_characterization.py`):
   - Keep as standalone or integrate as post-processing step
   - Define shared CSV format contract

### 5.2 Must-Avoid Pitfalls

1. **Do NOT use lowercase read commands** — Uppercase motor identifiers (`[rdA]`, `[rdB]`, `[rdC]`) are required per the November 14 investigation.

2. **Do NOT disconnect features from main flow** — If a feature is advertised in CLI help or README, it must be functional.

3. **Do NOT duplicate code** — Extract shared functionality to common modules to avoid the `h3_characterize.py` vs. `smc3_readback_diagnostic.py` duplication.

4. **Do NOT ignore the `--read-timeout` propagation bug** — Ensure `args.read_timeout` is passed to all code paths that perform readback polling.

5. **Do NOT assume hardware is connected** — Maintain the existing pattern of hardware-free testing via `FakeSerial`.
