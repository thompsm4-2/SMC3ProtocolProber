## 2. TX log findings

- 120 `READ`

All 191 rows report `status=OK`; all report `bytes_written=5` and `expected=5`. There are no non-OK TX rows and no recorded error strings.

There are 23 position commands each for A, B, and C. A and B remain at 512. Motor C's logged sequence is:

`512, 512, 492, 472, 452, 432, 412, 432, 452, 472, 492, 512, 532, 552, 572, 592, 612, 592, 572, 552, 532, 512, 512`

The 120 `READ` records transmit `[rdc]` requests. They do not contain received SMC3 response bytes. The TX file proves the serial write logger recorded full-length writes; it does not independently prove controller execution.

Sample indices run from 131 to 1352. The elapsed-time range is 15.057717–137.183753 seconds, a span of approximately **122.126 seconds**.

## 5. Gyro data-quality warning

Every recorded value in `gyro_x_dps`, `gyro_y_dps`, and `gyro_z_dps` is exactly zero in the complete sensor CSV, including during the commanded sweep.

This is a significant unresolved data-quality issue. Before using gyro values to estimate angular velocity, response time, or settling, verify:
- that the WT901C is actually transmitting nonzero gyro packets when moved;
- packet type and signed-value decoding;
- whether the reader is updating the gyro fields from fresh `0x52` packets;
- whether the logger is sampling the latest gyro data correctly;
- sensor configuration and output rate.

Do not silently replace zero gyro values with inferred values.

## 6. Preliminary angle behavior

Across sweep groups, the recorded angle means vary with position and path. Examples:

- Negative outbound: at offset -100, mean roll 1.386370°, pitch -1.396049°, yaw 5.449742°.
- Positive outbound: at offset +100, mean roll 1.374076°, pitch -1.352364°, yaw 6.515416°.
- Positive return at offset 0: mean roll 1.357597°, pitch -1.374337°, yaw 5.473022°.

The positive-return zero-offset group differs from the initial center reference by approximately:
- Roll: -0.001396°
- Pitch: +0.005109°
- Yaw: -0.184937°

These are sensor-reported differences, not a calibrated mechanical repeatability result. The yaw difference is especially difficult to interpret given its path dependence and the all-zero gyro channels.

## 7. Why no definitive degrees-per-count value is reported

The run contains only five distinct positions per directional leg, and the angles are small and path/time dependent. The yaw series is strongly direction-dependent. A simple slope can therefore encode time drift or AHRS/magnetometer behavior rather than a stable mechanical response.

The included analysis utility computes descriptive, direction-specific regressions from distinct group means. These are exploratory statistics only. They must not be adopted as final calibration constants.

## 8. What this run establishes

**Supported by the files:**
- A TX log was created.
- The logger recorded 191 full-length successful writes.
- The logged command sequence holds A/B at 512 and sweeps C through the specified sequence.
- The WT901C sensor log contains 622 rows, including center and sweep phases.
- The sensor reports angle changes during the sweep.
- All gyro channels in this file are exactly zero.

**Not established by these files alone:**
- That every command was executed by the SMC3 firmware.
- The returned contents of `[rdc]` requests.
- A validated degrees-per-count motor model.
- Reliable yaw mechanics.
- Angular velocity or settling time from gyro data.
- Whether all sensor values are fresh and correctly decoded.

## 9. Recommended next engineering work

1. Verify the WT901C packet parser using raw serial packet captures, especially `0x52` gyro packets.
2. Confirm that the sensor is physically producing nonzero gyro values during a safe manual movement.
3. Verify sensor mounting orientation and angle sign conventions.
4. Review the logger's phase timing and confirm the 3-second transition pauses are intentional.
5. Repeat Motor C characterization after sensor validation.
6. Use repeated cycles to distinguish mechanical hysteresis from sensor/AHRS drift.
7. Keep the raw logs and this report unchanged; create a new report for each new run.
